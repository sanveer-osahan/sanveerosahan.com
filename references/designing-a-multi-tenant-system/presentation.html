Requirements

Functional

  • Users can sign-up/sign-in using personal email or professional email.
  • User with personal email can create workspace or join another using invite code
  • User with professional email can create workspace or choose one their team already created
  • Signed-in user can switch between their workspaces or create a new one at any time
  • A user has to belong to at least one workspace.
  • Two workspaces cannot have the same name.

Out of scope

  • Users having roles in the workspaces when they join or create one.
  • The core features where a user creates, edits, views and shares resources in a workspace

Non-functional

  • A user should be able to only see the workspaces they are part of.
  • Members of one workspace cannot view or edit the resources of another
  • A user in many workspaces has isolated data and resources in each
  • Any upgrade to the system overall should be available on all the Workspaces.
  • Invite codes need to be cryptographically random (not sequential/guessable).
  • Log every create, join and switch with actor, timestamp and action, for compliance and debugging
  • Heavy usage on a few workspaces should not impact performance on other workspaces.

Out of scope

  • Data residency and regional compliance like GDPR - it starts to matter once real customer data is at scale
  • Disaster recovery and multi-region failover.
